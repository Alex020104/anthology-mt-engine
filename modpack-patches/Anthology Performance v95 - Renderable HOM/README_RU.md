# Anthology Performance v95 — Renderable HOM

Изолированный тест новой реализации `r__hom_dynamic`.

## Что изменено

- Прежний вариант проверял HOM внутри `r_dsgraph_insert_dynamic` для каждого дочернего visual после раскрытия renderable. На сложных NPC и объектах это многократно повторяло преобразование AABB и запрос к HOM.
- v95 оставляет существующую дешёвую проверку пространственной сферы, затем выполняет только один уточняющий HOM-запрос по world-space AABB целого renderable до вызова `renderable_Render()`.
- Скрытый целиком объект не раскрывается в дочерние меши и не создаёт для них render-пакеты.
- Частицы, HUD, PiP и специальные ненормальные проходы не затрагиваются. Геометрия, качество, LOD, тени, A-Life, Lua и сохранения не меняются.
- Эксперимент с дополнительным отсечением солнечных теней в версию намеренно не включён: он не относится к `r__hom_dynamic` и мог дать визуальный регресс.

Параметр включается автоматически:

```text
r__hom_dynamic on
```

Новая игра и очистка shader cache не нужны. Проверять нужно на том же сохранении и том же маршруте, особенно на базе с NPC за стенами и внутри помещений.

Быстрый откат без замены бинарника:

```text
r__hom_dynamic off
```

Ожидаемый маркер в логе:

```text
* [anthology/v95] one-box renderable HOM active
```

Для одного диагностического запуска можно включить `r__portal_traverse_stats 1` и `rs_stats on`. Строка `dynamic HOM box: test[...] reject[...]` покажет число проверок и реально отсечённых renderable. После замера вернуть `r__portal_traverse_stats 0` и `rs_stats off`.
