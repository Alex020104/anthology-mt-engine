# Anthology Performance v93 — Explicit A-Life Load Sweep

Изолированная проверка редких A-Life-тиков после загрузки сохранения.

## Что исправлено относительно v92

- Лог реального теста показал маркер аддона v92, но не показал движковый маркер прохода A-Life.
  Значит, `CALifeUpdateManager::shedule_Update()` не вызывался внутри окна `Device.dwPrecacheFrame`, и
  экспериментальный проход фактически не выполнялся.
- v93 вызывает один последовательный проход реестра напрямую после завершения загрузки графа уровня и
  до клиентского спавна. Это гарантированная точка загрузки, а не проверка состояния будущего кадра.
- A-Life остаётся на своём потоке-владельце. Объекты, Lua, smart terrain и граф не обновляются параллельно,
  поэтому новый вариант не добавляет гонок и не меняет порядок симуляции.
- После прохода немедленно восстанавливается штатный бюджет v88 — 0,090 мс. Дистанция A-Life 150 м,
  позиции NPC, рендер, PiP, SSS, Lua GC и игровые скрипты не меняются.
- Старый пятисекундный прогрев мира v70/v71 остаётся выключен: дополнительных кадров мира, скрытого
  рендера и зависания на «Зона ждёт» здесь нет.

Новая игра и очистка shader cache не нужны. Проверять следует на том же сохранении. Загрузка может
увеличиться на фактическое время первого прохода; его точная длительность будет записана в лог.

Ожидаемые маркеры:

```text
* [A-Life/v93] load first sweep processed N/N objects in X.XX ms; runtime budget restored to 0.090 ms
* [anthology/v93] explicit A-Life load sweep active; v92 trigger retired
```
